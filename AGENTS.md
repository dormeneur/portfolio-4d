# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project

Personal portfolio site (Aditya Bharti) built with Next.js 15 App Router, React 19, TypeScript, Tailwind CSS 3, and shadcn/ui. Originally generated by v0.dev and deployed on Vercel — the README notes v0.dev may auto-push changes to this repo, so expect occasional upstream commits not authored locally.

## Commands

Uses pnpm (pnpm-lock.yaml).

- `pnpm dev` — start dev server
- `pnpm build` — production build
- `pnpm lint` — ESLint via Next

There is no test setup. `next.config.mjs` sets `ignoreBuildErrors` / `ignoreDuringBuilds`, so a successful build does NOT prove type-safety — run `npx tsc --noEmit` to actually type-check.

## Architecture

- **Pages**: one folder per section under `app/` (`about`, `projects`, `experience`, `skills`, `resume`, `contact`, `hire-me`). All content (project lists, experience entries, etc.) is hardcoded as data arrays at the top of each `page.tsx` — there is no CMS, API, or data layer. Editing content = editing those arrays.
- **Layout** (`app/layout.tsx`): global chrome lives here — `Navbar`, `Footer`, `ProgressTracker`, `ScrollToTop`, and `ThemeProvider` with `forcedTheme="dark"`. The site is dark-mode only; don't build light-mode variants.
- **Components**: `components/*.tsx` are the handful of custom site components (navbar, footer, animated-section, etc.). `components/ui/` is the full stock shadcn/ui set — treat as vendored library code, add via `npx shadcn@latest add <name>`, and prefer these before writing new UI.
- **Styling**: `app/globals.css` is the active stylesheet (per `components.json`); `styles/globals.css` is leftover v0 scaffolding and unused. Path alias `@/*` maps to repo root.
- **Images**: `images.unoptimized: true` is set; some project images are remote Vercel Blob URLs, others live in `public/`.

## Gotchas

- Duplicate hook files exist (`hooks/use-toast.ts` vs `components/ui/use-toast.ts`, same for `use-mobile`) — v0 artifacts. Import from `@/hooks` per the `components.json` alias.
- Many dependencies are pinned to `"latest"` in package.json; the lockfile is the source of truth for actual versions.
